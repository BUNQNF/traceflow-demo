## 2. 视觉方向

- 核心表达：冷灰工作台。大面积低饱和蓝粉弥散光位于工作区背景底层，圆角白色工作区、多色协作块与渐变主操作形成有节奏的阅读路径。
- 交互重心：首页先回答项目是否健康；需求对照表先回答某条需求关联了什么；AI 页先回答建议是否可控；变更页先回答改哪里、谁来改、版本如何变。
- 色彩/字体/图形原则：`#F4F6F9` 冷浅灰画布、白色内容面；背景使用低透明度、强模糊的蓝/粉弥散层，不压过内容。主要提交操作使用小面积线性渐变，蓝紫、蓝绿、珊瑚紫分别对应普通推进、业务确认与版本创建；蓝、桃、淡紫、薄荷继续用于区分协作对象或状态区域，绿/橙/红仍表达通过/待处理/风险。正文使用 Noto Sans SC，编号和版本使用 Roboto Mono。状态均同时配有文字。
- 应避免的表现：营销页大标题、渐变、装饰性插图、单一紫色主题、以颜色作为唯一状态表达，以及冒充真实 Figma/Git/AI 集成。

## 5. 静态与动态资源边界

| 元素 | 实现方式 | 资源/格式 | 动态内容 | 说明 |
| --- | --- | --- | --- | --- |
| 工作台、表格、卡片、步骤条、版本对比 | DOM + CSS | 无位图依赖 | 是 | 由本地状态驱动，不截取为图片。 |
| 状态色与标识 | CSS Token + 文本 | 无 | 是 | 颜色和文案均随状态变化。 |

## 6. 响应式与安全区

- 基准尺寸：`1440px` 宽；内容区在左栏后以 `24px` 边距铺开。
- `1024px`：四视图卡改为 `2 x 2`，关联表仍保留主列；右侧详情收为抽屉。
- `768px`：侧栏收窄为图标栏或打开式抽屉；信息卡单列或双列，页底审核按钮保持可见。
- `375px`：侧栏变抽屉，表格改为“需求列表 + 详情抽屉”，每条详情按资产链路纵向展示；只保留查看、确认、审核和验收的关键动作。
- 安全区策略：移动端顶部栏和底部审核栏分别预留 `env(safe-area-inset-top)` / `env(safe-area-inset-bottom)`；不使用遮挡内容的浮动操作。
- 不可妥协项：任一状态都要显示版本、责任角色、明确状态文案和来源/关联对象。
- 可适配调整项：非关键的统计数字、动态列表密度、表格次要列和时间线文字可折叠进入详情。

## 7. 交付与技术约束

- 资源命名与导出：Figma 帧使用 `VF-xx · 名称 · TF-xx`；运行截图使用 `tf-xx-viewport.png`。
- 动效说明：仅使用 `150-250ms` 的状态淡入、侧栏/抽屉位移和 AI 分析加载反馈；尊重减少动态效果偏好。
- 可访问性/对比度：正文与背景达到可读对比；状态不能只依赖色彩；图标按钮在实现中提供 `aria-label` 和可见焦点。
- 技术可行性结论：均可由 HTML/CSS/React 与浏览器本地数据实现，不依赖真实外部系统。
- 已接受的视觉偏差：四张关键帧冻结视觉语言、层级与组件表达，不代表完整功能页面。T1/T2 中确认的功能、状态、权限与异常规则优先；T4 必须建立“需求/流程状态 -> 页面组件/交互”的实现对照，T5/T6 再补齐具体内容与行为。
